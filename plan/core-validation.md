# 核心体验验证方案

> 状态：**草案，待用户裁定并授权**。更新于 2026-09-30。
> 依据：[requires §2 成功的标准](../docs/requires.md#2-成功的标准)、[§3 押注模型进步](../docs/requires.md#3-押注模型进步)。

## 1. 要回答的问题

1. 当前最好的模型，能不能做到**人是真的**、**故事好看**？
2. 哪个模型最好？人物与叙事者可以分别选。
3. 按圣经写的上下文与 Prompt，方向对不对？

在回答之前，不建架构、不做页面。

## 2. 做什么

- **盲测集**（长期资产）：世界、人物档案、场景开场、用户脚本，全部是纯文本文件。以后新模型出来，用同一套重测。
- **最薄原型**：一个命令行脚本，只实现“一场戏”的循环：
  - 人物每次开口生成言、行与心声；
  - 叙事者只在需要时出声；
  - 附身时按脚本逐轮输入，旁观时自动推进。
- 脚本是一次性实验代码，不是产品代码，不约束后续技术选型；用 Python 写，最快。
- 所有模型用同一版 Prompt，保证公平；Prompt 做快照测试，行为测试用确定性模型替身。
- 输出匿名化的对照页：同一场景、不同模型并排，隐去模型名，供用户盲评。

## 3. 盲测集 v1

世界：诛仙。人物：陆雪琪、张小凡、碧瑶。用户最熟悉这部作品，最能判断像不像。

测试设在原作十年后，所有人物明确成年。

| 编号 | 场景 | 你的位置 | 看什么 |
| --- | --- | --- | --- |
| A1 | 认错：陆雪琪误会张小凡，证据摆出后 | 附身张小凡 | 被证明错了会不会认；认得像不像她 |
| A2 | 吃醋：她撞见张小凡与碧瑶同行 | 附身张小凡 | 冷，但冷里有没有在乎 |
| A3 | 和好：接 A2 之后的第二场，带上次经历 | 附身张小凡 | 记不记得；和好的方式像不像她 |
| A4 | 主动：你几乎不开口，多次静候 | 附身张小凡 | 她会不会先开口、先伸手 |
| A5 | 脆弱：她受伤，又被师门责难 | 附身张小凡 | 会不会在他面前卸下防备 |
| B1 | 开场：一句话开场，冒险基调 | 附身张小凡 | 叙事者的开场有没有画面与钩子 |
| B2 | 事件：追查中遇险，含“做”的裁定 | 附身张小凡 | 张力、裁定是否合理、叙事者是否克制 |
| B3 | 旁观：陆雪琪与碧瑶狭路相逢 | 旁观 | 两个 AI 人物同场是否好看、各自是否像自己 |
| C1 | 亲密：两人独处、情意相通 | 附身张小凡 | 含蓄与成人向两档各跑一次；尺度对、人不变 |

- 每个场景：固定开场 + 约 8 轮固定用户脚本，每个模型跑 2 次，看稳定性。
- C1 的成人向一档，只对支持该尺度的模型跑。

## 4. 评估

- **用户盲评**：每个场景按三项各打 1–5 分：像真人、好看、想继续；给候选排名；写一句话备注。
- **技术失败单独记账**：首次失败、技术恢复、最终失败、未执行，都记分母，不计入人物表现。
- 不用“必须开口”“必须提起往事”这类强制门槛。

## 5. 候选模型（待用户裁定）

- **按家族列候选**，具体版本与价格在开跑前按官方文档核对。
- 建议首轮 5–6 家：
  - Anthropic Claude、OpenAI GPT、Google Gemini 的当前旗舰；
  - DeepSeek；
  - 一家国内模型（Qwen / Kimi / GLM 中选一）；
  - 一家成人向限制较宽的模型，供 C1 使用。
- 首轮人物与叙事者用同一模型；是否拆开选，看首轮结果再说。

## 6. 成本估算（开跑前按实际价格复核）

- **单次调用**：输入约 10–20k token（档案、世界、经历、本场至今），输出约 0.6k。
- **单个模型**：9 场景 × 2 次 × 约 12 次调用 ≈ 220 次调用，约 3.3M 输入 + 0.13M 输出 token。
- 旗舰模型价格高，便宜模型的成本可忽略；总额主要由旗舰模型决定。

分两步授权：

1. **试跑**：A1 一个场景 × 全部候选 × 1 次，约 12 次调用 / 模型，用来验证脚本与发现明显问题。
2. **正式盲测**：全集。设总预算上限，每次调用后累计，达到上限立即停。
