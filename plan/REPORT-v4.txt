REPORT-v4：第一个可用版本

日期：2026-10-09
范围：技术设计 → 第一刀纵切实现 → 验证。全部在本地提交，没有推送、没有部署，提交信息里没有模型名。


一、做了什么

1. 小修与记录（已提交）
   - 群戏调度排除附身人物：Prompt 里说明“附身的人物不在可选之列，他什么时候开口由他自己决定”，解析时也拒绝，补了 Prompt、解析、整场行为三处测试，更新了快照（验证原型，Python 97 个测试通过）。
   - plan/core-validation.md §8.12 追加思考强度实验的结论：甲（默认推理）对话更好，乙（关闭推理）成人向细节更好；耗时中位数 3.2 秒 / 2.0 秒；决定产品默认开推理、固定首选服务商并回退、每次调用记录服务商；核心体验验证到此结束。“乙的成人向更好可能与推理设置有关”写成了“推测（未验证）”。
   - docs/requires.md 只改了 §2 末句和 §3 第三条，其余没动；AGENTS.md“工作入口”与 plan/CURRENT_WORK.md 同步为当前阶段。

2. 技术设计：docs/tech-design.md（草案）。形态、数据（按用户隔离、事件只追加、可见性规则）、模型接入、一场戏的调用链、失败、记忆、创作、接口、客户端、认证、留位、测试、待用户复核清单。

3. 实现（server/ 与 client/，scripts/start.sh，docker-compose.yml）
   - 服务端：JDK 25、Spring Boot 4.1、Spring MVC 阻塞式 + 虚拟线程、SSE、PostgreSQL 18（Flyway）。
   - 一场戏：说 / 静候时人物立刻开口（流式，一个气泡写完推一个），叙事者在幕后并发地决定要不要出声，出声的话排在人物之后；做时叙事者先裁定，人物再反应。心声随人物事件下发，客户端长按才显示。
   - 失败：空响应、截断、格式不合规、429 / 5xx 自动重试一次，仍失败就作为技术失败记录并显示，用户点重试只重做失败的那一步；不会变成人物的沉默，已说出口的不会被重抽。
   - 记忆：原始事件永久保存；散场后异步为每个在场人物（含被附身的）写回想和对在场人物的看法；下一场开始前补做缺失的；人物开口时看到档案、世界公共部分、与在场人物的关系、最近 2 场原文、更早场次的回想。
   - 创作：一句话 → 草稿 → 预览页手改 → 确认诞生（一个事务）。
   - 客户端：React + Vite + TypeScript，iMessage 式克制界面（无渐变、光晕、闪烁动画、徽章），PWA（manifest + 极简 service worker）。
   - 每次模型调用记录服务商、耗时、首字耗时、费用、token 与推理 token；可设费用硬上限；设置页可随时换各角色的模型。
   - 单个本地账号，口令从环境读；所有表带 user_id，复合外键保证子行不会挂到别人的父行上。

4. 提交（本地，未推送）：见 git log，共 8 次，按里程碑：小修与记录 / 技术设计 / 服务端核心 / 服务端测试 / 客户端 / 修正 / 文档。


二、怎么打开

   你的 .env 已经有 OPENROUTER_API_KEY；我给它追加了 LYNG_USER=me 和一个随机生成的 LYNG_PASSWORD（口令只在 .env 里，没有写进任何文档）。别人从零开始时：cp .env.example .env 再填写。
   scripts/start.sh            （Docker 起 PostgreSQL → 构建 → 运行）
   打开 http://localhost:8080，用 .env 里的 LYNG_PASSWORD 登录。
   不花钱地先看一遍：scripts/start.sh --fake

本机的数据库里现在留着冒烟测试的数据（一个“诛仙”世界，陆雪琪与张小凡，两场戏）。不想要的话：docker compose down 后删掉 .postgres-data/。

说明：Docker 本机能用，所以开发用 Docker Compose 的 PostgreSQL 18；测试用嵌入式 PostgreSQL（zonky，Apple Silicon 的二进制显式加了依赖），不依赖 Docker。


三、花了多少

   真实模型冒烟测试合计约 0.022 美元（授权 1 美元，没有碰到上限）：
   - 应用内记账（model_calls）：0.0186 美元，20 次调用（19 成功、1 次格式失败自动重试后恢复）。
   - 第一次创作调用（服务商被路由到 Relace，之后我清库重来）：0.0034 美元。
   - 为查服务商路由做的 3 次极小探测调用（max_tokens 5）：约 0.000002 美元。
   用到的调用：创作 2 次（含上面被清掉的那次）、两场戏的开场 2、人物 8、叙事者逐轮 6、收尾 1、回想 2（+1 次失败重试）。
   应用内的硬上限（LYNG_BUDGET_USD=1）全程开着。
   验证期以前的付费调用累计 6.79 美元，不变。

   实测延迟（Parasail，开推理）：
   - 开场 3.3 秒；人物一轮的首个气泡 3–5 秒，整轮 5–9 秒；叙事者逐轮决定（关推理）中位数约 1 秒；回想 2–3 秒；收尾 2.6 秒。
   - 创作 68 秒（推理 1939 token）；另一次 107 秒（推理 5307 token）。
   - 一次叙事者逐轮决定花了 20 秒：首选服务商没响应，OpenRouter 回退到了 Relace。那次叙事者还开着推理。


四、验证结果

   1. 全部测试通过：服务端 106 个、客户端 6 个、验证原型 97 个；客户端类型检查与构建通过。
   2. 用替身自动跑通了“创作 → 预览手改 → 第一场（说 / 做 / 静候）→ 结束 → 回想 → 第二场接上第一场”（server/.../web/ApiFlowTest），并验证了：技术失败可见且可重试、重试不重抽人物、用户隔离（含数据库层面的复合外键）、设置里换模型立即生效、费用硬上限。
   3. 真实模型冒烟测试走通了创作 + 两场双人戏，并用内置浏览器（手机尺寸）亲眼看了界面：气泡、动作行、叙事者居中、长按显示心声、结束与“再开一场”、失败提示与重试按钮。
      - 第二场的叙事者开场接上了第一场（写到“石桌上那根噬魂不在他手边”）；陆雪琪第二场里问“你的棒子呢”，用的是第一场里留在桌上的噬魂。
      - 陆雪琪的回想与对张小凡的看法读起来是本人口吻，记住了细节（“那半步算什么呢”）。
      - 失败的界面我是往库里插了一条失败事件来看的，然后点了重试，真实模型接上了；不是模型自然失败出来的。


五、还有哪些问题

   1. 我没能验证 PWA 能不能装到手机桌面：内置浏览器里 service worker 注册失败（“fetching the script” 未知错误，服务端返回正常，推测是内置浏览器的限制），manifest 的类型是对的。在非本机地址上装 PWA 还需要 HTTPS，部署不在这一刀。
   2. 创作慢（1 到 2 分钟）且质量一般：会编造原作细节（比如说张小凡在七脉会武胜了陆雪琪、碧瑶之魂封在合欢铃里），Prompt 已要求不确定就不写，仍需要在预览页改。创作可以在设置里换更强的模型，或把 creation 写成“模型@low”。
   3. 叙事者仍会替人物写动作：收尾里写了“陆雪琪踏出门去，靴声很轻”，违反“叙事者不替人物决定”。Prompt 里有这条规则，模型没守住；这是 Prompt 与模型的问题，没做处理。
   4. 人物的“行”仍偏长（验证期遗留，圣经 §4.7）。
   5. 首选服务商 DeepSeek（模型出品方）被 OpenRouter 账号隐私设置挡住，现在用 Parasail，样本很小。服务商偶发无响应时回退要等很久（20 秒那次）。
   6. 回想的格式失败过一次（模型在标签前多写了文字），自动重试后恢复；回想质量没有盲测，只有这几个样本。
   7. 叙事者“逐轮决定”在“说 / 静候”时看不到人物这一轮的回应，所以它的出声可能与人物刚做的事重复或错位；本次几轮里没看到问题，但没有系统评估。
   8. 服务中途重启可能留下“用户出手了但没人回应”的一轮：说 / 静候的情况能识别并让用户点重试；“做”之后叙事者已出声而人物未反应的情况识别不了。
   9. 场锁在进程内，只支持单实例；登录没有限流；没有 HTTPS。都不影响本机使用，部署前要补。
   10. 没做：旁观、群戏、穿越、路人留下、成人向开关、撤回用户的话、世界事实、在场新建人物（都在 tech-design §12 留了位置）。


六、待用户复核的决定清单（详见 docs/tech-design.md §13，依据与可信度写在那里）

   1. 首选服务商 Parasail（fp8），允许回退；没有取 DeepSeek 出品方。是否放开 OpenRouter 的账号隐私设置，由你决定。
   2. “说 / 静候”时叙事者与人物并发、叙事者排在人物之后；“做”时叙事者先出声。
   3. 流式气泡是暂定的，校验失败会撤回并自动重试一次。
   4. 回想一次调用同时产出“回想”和“对在场人物的看法”，用带标签的纯文本。
   5. 人物看最近 2 场的原文，更早的看回想。
   6. 叙事者只看上一场的公开原文，不看回想。
   7. 回想异步生成，下一场开始前补做缺失的；补不上就退回原文。
   8. 创作输出用带标签的纯文本，不用 JSON。
   9. 单账号，口令在 .env 的 LYNG_PASSWORD（我生成的，并追加进了你的 .env）。
   10. 开发用 Docker Compose 的 PostgreSQL；测试用嵌入式 PostgreSQL。
   11. requires §6 的“模型选型靠盲测”没改，与 §2、§3 的新写法略有出入，建议同步。
   12. 本刀不做撤回用户的话。
   13. 技术失败的重试只重做失败的那一步，条件与第一次相同。
   14. 叙事者逐轮决定默认关闭推理（单独一个角色），与你定的“产品默认开推理”有出入：它只决定要不要出声，冒烟测试里开着推理有一次花了 20 秒。
   15. 创作用默认推理，一次 1 到 2 分钟。
   16. 费用硬上限按库里累计费用在每次调用前检查，并发时最多超出一次调用的费用。
   17. “叙事：无。”这类带句号的“无”算不出声（模型真的会这样写）。
   18. 技术栈版本：Spring Boot 4.1.1（当前稳定版；3.5 已过开源支持期）、Jackson 3、PostgreSQL 18、React 19、Vite 8、TypeScript 7、Vitest 5。
