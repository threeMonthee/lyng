# 产品圣经

> 状态：**草稿，待用户审阅**。更新于 2026-09-30。
> 上位文档：[requires.md](requires.md)。本文定义领域概念、它们的关系与已确认决定。标“待确认”的条目是建议，不是事实。

## 1. 概念总览

首版只有五个概念：

| 概念 | 一句话 |
| --- | --- |
| **人物** | 活着的人，有档案与连续人生；由 AI 驱动，或被用户接管 |
| **世界** | 人物所处的设定：时代、地理、规则、势力，可来自原作 |
| **场景** | 一次见面：某世界某地某时，若干人物在场，有开场与结束 |
| **叙事者** | 不是人物；让世界运转的声音 |
| **经历** | 人物亲历过的事，是记忆的原料 |

不再有：用户身份 / 主身份、人物与身份的二分、原型、初见确认、永久会话、消息、未读。

## 2. 人物

- 人物是活着的人。性格是底色，TA 会被经历与在乎的人改变（见 [requires §2](requires.md#2-最高原则人物是活着的人)）。
- **档案**用叙述写成，不用标签表：小传、外在与内心的反差、在乎一个人时的样子、如何和好。
- 人物有**故乡世界**。
- 待确认：人物同一时刻只在一个场景中。
- 人物只知道自己经历、看到、听到的事（有限认知）；不同人物对同一件事的认识可以不同。
- 待确认：人物不知道自己是虚构的。
- 待确认：档案在诞生时留下快照，此后的人物由经历塑造，档案不随意回写。

## 3. 世界

- 世界是设定，可来自原作，也可原创。
- 世界事实：叙事者裁定的行动结果记为世界事实（如“张小凡左臂受伤”），此后在这个世界里延续。
- 不做数值、背包、任务。
- **穿越**：人物进入故乡以外的世界即穿越。TA 带着全部记忆，对新世界只有有限认知；叙事者在开场交代 TA 如何到来。

## 4. 场景（见面）

- 场景 = 世界 + 地点 + 时刻 + 在场人物。用户定开场处境，叙事者写开场。
- 一场戏中，用户接管一个人物；其余在场人物由 AI 驱动，各自是完整的自己。待确认：同一场戏中途能否换接管对象。
- **群戏**：首版支持多个 AI 人物同场。每个人物只感知场上公开发生的事与自己的心事，看不到他人的心声。待裁决：谁在何时开口（发言轮次）。
- 场景结束后，场上发生的事成为在场人物各自的经历（按各自所见）。
- 呈现：叙事者文字与人物言行在视觉上可区分；人物言行合一成段，带姓名；用户所扮人物的言行与他人区分。
- 用户有两种正式的表达：**说**与**做**。“做”由叙事者润色为叙述并裁定结果。（形式待功能设计）
- 待确认：用户可以选择不开口、静候其他人物，但不强迫任何人说话。
- 待确认：谁结束一场戏——用户结束，或叙事者在自然收尾处提议结束。

## 5. 叙事者

- 叙事者不是人物，不与人物建立关系。
- 职责：描写环境、代演路人、推进事件、裁定行动结果。
- 开场只使用用户给定的处境；未提供的共同经历、地点、对白保持未指定，不替人物补写过去。
- 叙事者不替人物说话或做决定；人物的言行只来自人物自己（或接管 TA 的用户）。

## 6. 接管与交还

- 用户可完整接管任一人物，也可交还给 AI。
- 接管期间，该人物的 AI 心智不运行；用户以 TA 所说所做，就是 TA 的亲历。
- 交还后，AI 把这段经历继承为“自己做过的事”；人物**永远不知道**自己被接管过。回想时 TA 可以用自己的方式理解“那时为什么那样”。

## 7. 经历与记忆

- 原始经历由系统自动保存与召回，不依赖模型主动“记住”；每条材料显式标注说话人与对象。
- 人物开口时看到完整的关系与处境；旧台词作为感知材料提供，不作为模型的对话历史回放。
- 回想、整理、关联在场景结束或批量时异步进行，不每轮同步追加模型调用。
- 模型产生的关联只作带来源的线索，不升级为事实。

## 8. 心声

- 心声是人物此刻没说出口的一两句，与该段言行同次生成，默认隐藏，轻量可看。
- 心声不是运行记录；完整调试信息另行处理，不进入产品体验。

## 9. 离线

- 用户离线时人物不运行，世界静止。
