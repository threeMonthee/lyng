## 1. 产品是什么

lyng 是用户自己使用的作品，不追增长。

用户创造喜爱的人物，让 TA 们拥有连续的人生与记忆，并与 TA 们长期相处。相处的方式是**见面**：用户接管某个人物走进一个场景，与其他人物面对面；AI 叙事者让场景所在的世界运转。

核心体验按重要性排列：

1. **被在意**：人物记得你、想你、会主动，会为你改变。
2. **沉浸扮演**：像身处一个故事，而不是在操作一个聊天软件。
3. **长期相处**：关系有历史，今天的见面接着昨天。

窥见人物内心不是首要卖点，只以轻量的“心声”存在。

## 2. 最高原则：人物是活着的人

- 人物有连续的人生与记忆。TA 经历过的事会留下来，并影响之后的 TA。
- 性格是底色，不是铠甲。人物不以“维护设定”为首要任务。
- **不讨好，但会爱。** 真实的人会为在乎的人改变：会软化、认错、让步；有情绪起伏与脆弱；会主动。
- 立场可以坚持；事实错误被指出并证明时，应当承认。
- 人物之间的冷暖来自关系与处境，不来自标签。

与本原则冲突的机制、Prompt 或 Provider 适配，以本原则为准。

## 3. 首版范围

### 3.1 要做

| 能力 | 要求 |
| --- | --- |
| 人物 | 创建人物；人物有档案与连续人生，跨场景、跨世界保持记忆 |
| 世界 | 人物可进入世界 / 故事；世界有设定，可来自原作 |
| 场景（见面） | 一次见面发生在某个世界的某地某时，有在场人物、开场与结束；结束后成为在场人物的经历 |
| 群戏 | 一场戏可有多个 AI 人物同场，各自以完整的自己参与 |
| 叙事者 | 描写环境、代演路人、推进事件、裁定行动结果；行动结果记为世界事实 |
| 接管 | 用户可完整接管任一人物，并交还给 AI |
| 穿越 | 人物可离开故乡世界进入其他世界，带着全部记忆 |
| 心声 | 轻量查看人物此刻没说出口的想法 |
| 创作 | 从简短描述生成人物与世界，保留预览确认，步骤大幅压缩 |

### 3.2 不做

- **消息体系**：不做 IM 式私聊、未读、消息列表。交流形态统一为见面。
- **游戏数值**：不做属性、背包、任务、好感度数值。
- **离线运行**：用户离线时人物不运行，世界静止。
- **运行记录式的观察页**：调试信息另行处理，不进入产品体验。
- **增长功能**：产品不追增长，不为此做分享、社区等功能。

## 4. 体验要求

### 4.1 见面

- 一场戏读起来像小说，外壳像 iMessage / 微信一样克制。
- 用户的**言与行都有正式的表达方式**，不靠括号。
- 人物的言行合在一起呈现，说话人始终明确。
- 叙事者的文字与人物的言行在视觉上可区分。

### 4.2 身份即人物

- 不区分“用户身份”与“AI 角色”：用户在场景中就是某个人物。
- 接管期间用户以该人物所说所做，交还后算该人物亲历；人物不知道自己被接管过。

### 4.3 连续与记忆

- 人物的原始经历由系统自动保存与召回，不依赖模型主动“记住”。
- 人物只知道自己经历、看到、听到的事。

### 4.4 离线

- 离线即静止：用户不在时不发生任何事。
- 回到 App 时的行为暂不改变，具体待功能设计。

### 4.5 创作

- 从一句话描述开始（如“诛仙，青云大试后，陆雪琪”）。
- AI 生成世界概要与相关人物；只在发现冲突时提示。
- 一页预览，可手改或让 AI 局部改；确认后诞生。
- 从描述到第一场开场，用户操作步骤尽量少（目标约 4 步）。

### 4.6 视觉

- 克制：去掉渐变、光晕、墨晕、闪烁思考动画、多余状态标签与徽章。
- 系统字体、单一强调色；人物肖像是唯一视觉主角；状态文案收成一个词。

## 5. 质量底线

- **失败不伪装**：模型失败、空响应、截断必须作为技术失败呈现，不能表现为人物沉默或人物的选择。
- **说话那次生成看到全部**：人物开口时必须看到完整的关系与处境；记账、回想等整理工作不每轮同步追加模型调用。
- **行为可验证**：人物行为有行为测试；Prompt 有快照测试；测试默认使用确定性模型替身。
- **模型选型靠盲测**：效果优先，可用海外更强模型；以同场景盲测选型，换模型、Prompt、上下文或调用链后受影响结论重验。
