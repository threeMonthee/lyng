## 1. 这是什么

此间有灵（Lyng）2.0：进入你喜爱的作品世界，和多个像真人一样的人物相处，亲身经历故事（含成人向）。

它是 [x-chat-ai](https://github.com/threeMonthee/x-chat-ai)（此间有灵 1.0）的 2.0 版本，在本仓库从零重写：

- **形态**取 lyng 定稿的产品：世界、叙事者、面对面的一场戏、附身与旁观、群戏。
- **内核**取 x-chat-ai：人物的心智与记忆、私聊、一念生创作、人物主页、心智观察。x-chat-ai 的大部分功能迁移过来。
- 不在两个前身的代码上修改；盲测验证过的 Prompt 写法与解析规则沿用，其余只借鉴实验结论与踩过的坑（[reference/lessons.md](reference/lessons.md)）。

现阶段只给用户自己用；稳定后可能做成 C 端产品，现在不做但不堵路。也借这个项目跟上 AI 的发展。

## 2. 成功的标准

两条，缺一不可：

1. **人是真的。** 人物像一个真人，不是在执行设定：有连续的人生与记忆；性格是底色不是铠甲；不讨好，但会爱，会软化、认错、让步；有情绪起伏与脆弱；会主动。
2. **故事好看。** 世界有自己的动静，有张力、悬念、意外与余味，每一场戏都给人再来一场的理由。

而且要**像一个产品**，不是演示：每个页面的加载、空、失败、等待、中断都有正式的样子，手机和电脑都好用。

## 3. 押注模型进步

- **框架薄，模型厚。** 给模型完整的处境与关系，让它自己演；不在模型短板周围堆补偿机制。
- **系统只在边界上负责**：经历的保存与召回、说话人标注、失败识别、内容尺度、记账。人物怎么感受、记住什么、怎么看人，由人物自己决定。
- 同场景盲测集长期保留，换模型或大改 Prompt 时用来对比；改了模型、Prompt、上下文或调用链，受影响的结论不继承。

## 4. 第一版范围

1. **一念生**：一句话描述世界与人物 → 必要追问（如原作人物的人生时期）→ 一页预览 → 手改、让 AI 局部改、一致性检查 → 诞生。先有世界再有人物；之后可在已有世界里添人物。
2. **人物的内心**：出生档案（封存）＋ 如今的自我、对每个人的看法、牵挂、带个人意义的记忆。原始经历全部自动保存；更早的经历由系统按相关性召回，人物也能自己去翻。
3. **你**：附身任一人物亲身经历，或隐身旁观。你新建的人物也是普通人物，你不附身时由 AI 演。
4. **一场戏**：面对面，叙事者推动，双人戏与群戏，说 / 做 / 静候 / 继续，随时切换身份；你结束，叙事者收尾，散场后人物各自整理内心。
5. **私聊**：附身一个人物，与另一个人物一对一文字交流。永久会话、流式、继续、有动机的沉默、未读；你上线时人物可能主动来找你。私聊与一场戏进入同一段人生。
6. **人物主页**：出生档案、如今的自我、牵挂、记忆、TA 怎么看每个人、亲历的戏与私聊。只读。
7. **心智观察**：平时只看心声；幕后能看每次生成的上下文、思考、工具调用、保存了什么、失败与重试。
8. **内容尺度**：全局开关，默认含蓄留白，可切成人向（只涉及成年人物）。
9. **记账**：每次模型调用记录服务商、费用、耗时与 token，可设费用上限。

**第一版不做**：部署与登录（单人本机使用）、AI 肖像、穿越、路人留下、世界事实、原生 App、图片与语音消息、自动连续运行。

## 5. 质量底线

- **失败不伪装**：模型失败、空响应、截断、格式错误作为技术失败呈现并可重试，不能表现为人物沉默或人物的选择。
- **说出口不能重来**：已经成为经历的言行不能重抽、不能改。
- **说话的那次生成看到全部**：人物开口时看到自己的档案、自我、对眼前人的看法、牵挂与相关记忆；整理内心放在一场戏或一段私聊之后，不压在每一轮的表演上。
- **行为可验证**：人物与一场戏的行为有测试；Prompt 有快照测试；测试默认使用确定性模型替身。
- **C 端不堵路**：数据从第一天起按用户隔离；每次模型调用记录成本。走向 C 端前要解决的原作版权、成人向合规、单用户成本、认证与部署，现在只登记。

## 6. 技术与流程约束

- 服务端 Java 25 + Spring Boot，阻塞式 + 虚拟线程；PostgreSQL + pgvector。
- 前端选最适合 AI 智能体开发的技术栈：React + TypeScript + Vite + Tailwind + shadcn/ui；一套响应式网页，电脑与手机浏览器都能用。
- 模型经 OpenRouter，默认 DeepSeek V4.1 Flash 开推理、首选服务商 Parasail；记忆向量用百炼 qwen3.7-text-embedding。
- 付费模型调用、部署、推送、凭据遵循 [AGENTS.md](../AGENTS.md) 的硬线。
