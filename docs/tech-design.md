# 技术设计：第一个可用版本

> 状态：**2026-10-10 重写**，取代 10-09 的草案及其实现。产品含义以 [requires.md](requires.md) 与 [PROJECT_BIBLE.md](PROJECT_BIBLE.md) 为准，本文只回答“怎么做”。
> 用户在 2026-10-10 的要求：旧实现做得不好，0→1 重写，用最精简的代码；放弃响应式，用虚拟线程与传统阻塞式；客户端与界面重做，暂时不需要移动端，先把网页做精美。其余取舍由 agent 决定，决定与依据集中在 [§1](#1-决定一览)。

## 1. 决定一览

| # | 决定 | 依据 | 代价 |
| --- | --- | --- | --- |
| 1 | **每一轮统一为“叙事者先行”**：用户动作 → 叙事者（叙事；群戏再加“轮到”）→ 被点到的人物依次开口 | 验证原型就是这条调用链，盲测结论都建立在它上面（[core-validation](../plan/core-validation.md) §8）。10-09 版把“说”改成叙事者与人物并发，换来叙事者看不到人物回应、两套顺序、撤回与补偿机制（REPORT-v4 第 7、8 条）。统一以后，附身、旁观、双人戏、群戏走同一段代码 | “说”之后人物要晚一次叙事者调用才开口。叙事者逐轮决定关推理，冒烟测试中位数约 1 秒；服务商回退时有长尾 |
| 2 | **SQLite 单文件**（`data/lyng.db`），启动时建表 | 自用、单进程、低并发；去掉 Docker、Flyway、嵌入式 PostgreSQL。纯 SQL，走向 C 端时迁移成本低 | 单进程单写者；部署多实例前要换库 |
| 3 | **不做登录**，服务只监听本机 | 现阶段只在本机桌面浏览器用（用户 10-10：暂不需要移动端）。数据仍按 `user_id` 隔离，不堵 C 端的路 | 对外开放前要补认证、HTTPS |
| 4 | **模型配置只走环境变量**，不做设置页 | 少一页、少一张表；换模型是低频操作，重启即可 | 换模型要重启 |
| 5 | **失败不进事件流**：场景上记“这一轮还剩哪几步”和失败原因，重试从剩下的那一步接着做 | 失败不属于世界，任何人物都感知不到；一个字段代替 10-09 版的 failure / resolved 事件与推断逻辑；服务中途重启后也能接着做 | — |
| 6 | **流式按段推送**：人物的一段“行”或“说”写完就推给页面，整次生成校验通过才落库 | 延迟是首要风险，首段比整轮早出现几秒 | 校验失败时页面要收回已显示的段（只发生在技术失败时） |
| 7 | **桌面网页**，不做 PWA；心声改为**点击**人物的话查看 | 用户 10-10：先把网页做精美。圣经的“长按”是手机手势，桌面上用点击，含义不变：默认隐藏，主动查看才显示 | 以后做移动端时补长按 |
| 8 | **回想在散场后异步生成；开场前补齐**在场人物缺的回想 | 不阻塞散场；“开场前补齐”是唯一的保证路径，丢失、失败都不丢连续性 | 回想失败时，下一场开场要多等一次调用 |

## 2. 范围

**做：**

1. 一句话创作世界与人物（或在已有世界里添人物）→ 一页预览，可手改 → 诞生。
2. 开一场戏：选世界、在场人物（一个或多个）、附身谁或旁观、基调、开场处境 → 叙事者开场。
3. 一场戏里：附身时说 / 做 / 静候；旁观时点“继续”走一段；**随时切换**附身的人物或转为旁观；双人戏与群戏；流式；点击看心声；由你结束，叙事者收尾。
4. 散场后每个在场人物写回想与对其他人的看法；下一场接得上。
5. 人物页：档案、TA 记得的事、TA 怎么看某人、TA 经历过的场景，都只读。
6. 技术失败看得见、可以重试；每次模型调用记账，可设费用硬上限。

**不做（留位）：**

| 功能 | 留位 |
| --- | --- |
| 穿越 | 人物有故乡世界（`characters.world_id`）；开场时允许选别的世界的人物，叙事者 Prompt 加“来路” |
| 路人留下 | 复用创作预览；新人物的诞生带上这一场的经历 |
| 世界事实 | 叙事者裁定的结果，随散场整理成 `world_facts` |
| 成人向开关 | `scenes.scale` 已有，Prompt 两档已有；需同意检查（原型有） |
| 生死须同意 | 目前叙事者 Prompt 明确“这一场里不要裁定任何人物死去或永久失去” |
| 撤回自己的话 | 叙事者先行后，用户的话与回应之间有一次调用的空隙，可以在那时撤回 |
| 预览里让 AI 局部改 | 现在只能手改 |
| 移动端、登录、部署 | 数据已按用户隔离 |

## 3. 形态

```text
浏览器（React + Vite + TypeScript，桌面网页）
   │  JSON；会跑模型的动作用 POST 返回 text/event-stream
   ▼
Java 服务（JDK 25，Spring Boot，Spring MVC 阻塞式 + 虚拟线程）
   ├─ model   模型网关：OpenRouter 流式客户端、确定性替身、重试、记账、预算
   ├─ story   标记解析、Prompt、一场戏、回想、创作
   ├─ store   SQLite 读写
   └─ web     接口与 SSE
   │  JDBC
   ▼
SQLite（data/lyng.db）                    OpenRouter（OpenAI 兼容接口）
```

- 一个进程、一个数据库文件；构建好的客户端由 Java 服务同源托管。开发时 Vite 代理 `/api`。
- SSE 在请求线程里同步写出、逐条 flush；客户端断开后这一轮照常跑完并落库，刷新后从数据库恢复。

## 4. 数据

所有表都带 `user_id`（现阶段固定为 `me`），所有查询都带它。

| 表 | 内容 | 可变？ |
| --- | --- | --- |
| `worlds` | 名字、公开设定、只有叙事者知道的设定 | 诞生后不改 |
| `characters` | 故乡世界、姓名、叙述式档案 | 诞生后不改（圣经 §3.2） |
| `scenes` | 序号、世界、在场人物、当前附身的人物（空 = 旁观）与旁观时跟随的人物、基调、尺度、开场处境、状态、**未完成的步骤**与失败原因 | 身份、步骤、状态会变 |
| `lines` | 这一场里发生的事，**一行一件**：叙事、说、行、没有开口、心声；标明说话人、轮次、是否出自用户 | **只追加** |
| `memories` | 每个人物每场一条：回想（TA 的口吻）与对在场其他人的看法 | 整理产物，可重新生成 |
| `model_calls` | 每次尝试一行：用途、模型、服务商、费用、耗时、首字耗时、token、推理 token、结果、错误 | 只追加 |

**可见性**：叙事、说、行、没有开口对在场所有人可见；心声只有本人可见。失败不在 `lines` 里，所以天然不进任何人物的感知。散场后“成为各人的经历”不复制数据：各人的经历就是按这条规则对 `lines` 的视图。

**被附身过的事**：`lines.by_user` 只用于界面（右侧显示、“你”）。写进人物上下文时与其他行完全一样，人物不知道自己被附身过（圣经 §2.3）。

## 5. 一场戏

### 5.1 步骤

一场戏要做的事都是“步骤”：`opening`（开场）、`narrator`（这一轮叙事者的决定）、某个人物的 id（这个人物开口）、`closing`（收尾）。场景上记着**还剩哪几步**：

```text
建场景         → 剩 [opening]
用户动作       → 写下用户的那一行 → 剩 [narrator]
narrator 成功  → 写下叙事（若有）→ 剩 [被点到的人物…]
人物成功       → 写下 TA 的行 → 去掉这一步
closing 成功   → 写下收尾 → 场景结束 → 异步回想
```

每一步成功就落库并推进；失败就停在这一步，记下原因。“重试”就是从剩下的第一步接着做，条件与第一次相同：人物重试时看到的，只到失败发生的那一刻为止。已经落库的行没有任何改写或重抽的接口（圣经 §3.4）。

同一场同一时刻只跑一件事（进程内场锁）；有未完成的步骤时不能做新动作，也不能切换身份。

### 5.2 一轮

| 你的身份 | 动作 | 写下的行 | 叙事者的“刚刚” |
| --- | --- | --- | --- |
| 附身 | 说 | `张小凡（说）：…` | 同左 |
| 附身 | 做 | `张小凡（行）：…`（原文成行，一字不改） | 同左 |
| 附身 | 静候 | `张小凡没有开口。` | 同左 |
| 旁观 | 继续 | 不写 | `没有新的动作。` |

然后叙事者决定这一轮：

- **双人戏**（只有一个 AI 人物）：只写 `叙事：…`，不调度，那个人物每一轮都接戏，接不接由 TA 决定。
- **群戏**：写 `叙事：…` 与 `轮到：…`，被点到的人物按顺序开口；附身的人物不在可选之列。旁观时这一轮必须往前走（叙事与轮到不能都是“无”）。

人物开口时看得到这一轮叙事者刚写的东西，也看得到同一轮先开口的人。

### 5.3 切换身份

无事在跑、也没有未完成的步骤时，可以改成附身在场的另一个人物，或转为旁观（选择跟随谁）。至少要留一个 AI 人物在场。切换只改场景上的身份，不写任何行；下一次 Prompt 按新身份装配。

### 5.4 结束

你点“结束这场戏” → 叙事者收尾（一两句，留一个想继续的理由）→ 场景结束 → 为每个在场人物异步写回想（含被附身过的人物：做过的算数，怎么看待由 TA 自己）。收尾失败时可以重试，也可以不要收尾直接结束。

## 6. 上下文

Prompt 原文从验证原型逐字移植，叙事者的 Prompt 与原型快照逐字节一致（平行测试，见 §11）。所有材料都是标明说话人的“感知材料”，放在 user 消息里，不作为 assistant 历史回放。

**人物开口时看到：**

1. system：身份与分寸、世界的公开设定、自己的档案、**对在场其他人的看法**（最近一条回想里的）、**更早场景的回想**（最近 2 场之外，最多 20 条，由旧到新）；
2. user：**最近 2 场**已结束场景里 TA 感知到的原文（含自己的心声）、**这一场到现在**、本轮要求与写法。

回想缺失时退回原文：宁可长一点，也不让人物忘了一场戏。

**叙事者看到：**两份世界设定、在场人物的档案、你的身份（附身谁，或镜头跟随谁）、基调、分寸、开场处境、这个世界最近一场已结束场景的公开原文、这一场的公开经过。看不到任何人的心声与回想。

## 7. 记忆

- 原始经历就是 `lines`，永久保存。
- 回想：每个在场人物一次调用，输出 `回想：…`（第一人称，三五句）与对每个其他在场人物的 `看待<姓名>：…`。输入是 TA 的档案、此前对他们的看法、这一场里 TA 的所见所闻（含自己的心声）。
- 散场后异步生成；**下一场开场前**，为在场人物补齐所有缺的回想（先等进行中的，再补做）。
- 人物页展示“TA 记得的事”“TA 怎么看某人”，只读（圣经 §6.1）。

## 8. 创作

1. 一句话（可选：已有世界，此时只写人物）。
2. 一次调用，输出带标记的纯文本（不用 JSON）：`【世界名】`、`【世界·公开】`、`【世界·只有叙事者知道】`、若干 `【人物】姓名` 与叙述式档案。描述里写了几个人物就写几个。
3. 解析成草稿返回页面（不落库）；格式不合规按技术失败处理，可重试。
4. 预览页全部可手改；确认后在一个事务里诞生世界与人物。

## 9. 模型接入

- `ChatModel` 接口两个实现：OpenRouter（`java.net.http`，一律流式读取，解析费用、实际服务商、推理 token）与确定性替身（测试和 `--fake` 模式，不发网络请求）。
- 网关：费用上限检查 → 调用 → 校验（截断、空响应、格式）→ 记账。429、5xx、网络错误、空响应、截断、格式不合规**自动重试一次**；服务商拒绝、401 / 402、费用上限不重试。仍失败就交给调用方，作为技术失败呈现，绝不当成人物的沉默。接口没返回费用的成功响应视为故障。
- 角色：人物、叙事者（开场与收尾）、叙事者逐轮决定（默认关推理）、创作、回想。每个角色可以单独用环境变量指定 `模型ID` 或 `模型ID@推理设置`。
- 首选服务商写成 OpenRouter 的 `provider.order` 并允许回退；每次调用记下实际服务商。

## 10. 接口

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/overview` | 侧栏需要的一切：世界、人物、场景列表、累计费用 |
| `GET /api/worlds/{id}`、`GET /api/characters/{id}` | 世界详情；人物详情（档案、记得的事、看法、场景） |
| `POST /api/drafts` | 一句话 → 草稿 |
| `POST /api/births` | 确认诞生 |
| `POST /api/scenes` | 建一场戏（剩 `opening`） |
| `GET /api/scenes/{id}` | 一场戏的全部行、身份、未完成的步骤、是否正在跑 |
| `POST /api/scenes/{id}/act` | 说 / 做 / 静候 / 继续（SSE） |
| `POST /api/scenes/{id}/resume` | 从剩下的第一步接着做：开场、重试都是它（SSE） |
| `POST /api/scenes/{id}/end` | 收尾并结束；`{"closing": false}` 不要收尾（SSE） |
| `PUT /api/scenes/{id}/identity` | 切换附身的人物或转为旁观 |
| `GET /api/usage` | 累计费用、上限、最近的调用 |

SSE 事件：`line`（已落库的一行）、`draft`（人物正在写的一段，暂定）、`reset`（收回某人物的暂定段）、`typing`（谁在写：叙事者或某个人物）、`done`、`failed`（这一步技术失败，原因）。流结束后页面重新读一次场景，以数据库为准。

## 11. 客户端

React + Vite + TypeScript，桌面网页，不引入路由、状态管理与组件库。

- **布局**：左侧栏（场景、世界与人物、创作、新的一场、用量）+ 右侧主区。像 macOS 的“信息”：克制、留白、系统字体、一种强调色，浅色与深色两套。
- **一场戏**：叙事者居中、浅色；人物的话是气泡，带姓名与头像（姓名首字，颜色由姓名决定、低饱和）；动作是气泡之间的一行浅色文字；**你附身的人物在右侧**。点击人物的话显示或收起心声。底部：说 / 做切换、输入框、静候（旁观时只有“继续”）。顶部：在场人物、身份切换、结束。
- **状态要说清楚**：谁在写（朴素的省略号，不闪烁）、技术失败写在失败的位置并带“重试”、创作的等待提示已用时间。
- 去 AI 味：无渐变、光晕、闪烁动画、徽章、多余的状态标签。

## 12. 测试

- **Prompt 快照**：每个 Prompt 一份；叙事者的开场、双人戏一轮、群戏一轮（附身）、旁观一轮、收尾，与原型快照逐字节一致。
- **标记与流式切段**：从原型移植的格式用例；逐字符喂入的流式用例。
- **一场戏的行为**（确定性替身 + 真实 SQLite + 完整 Spring 应用）：叙事者先行、做的结果先于人物反应、静候与不开口、附身的人物从不由模型驱动、群戏按“轮到”的顺序开口、旁观时的“继续”、切换身份、心声只有本人看得到、技术失败不是沉默且只重试失败的那一步、重试看到的与第一次相同、散场写回想（含被附身过的人物）、第二场接上第一场、更早的场景只经由回想、记账与费用上限。
- **接口流程**：通过 HTTP 走完“创作 → 第一场 → 结束 → 第二场”。
- 真实模型只用于冒烟测试，须在对话里单独授权场景与预算。

## 13. 已知风险

- **延迟**：叙事者先行多一次串行调用；服务商波动的长尾仍在。`model_calls` 记着每次的耗时与服务商，供事后看。
- **叙事者质量**：REPORT-v4 里叙事者替人物写动作、人物的“行”偏长，是 Prompt 与模型的问题，这次重写没有改 Prompt。
- **回想质量**：没有盲测，它决定第 3 场起的连续性。
- **上下文增长**：靠“近 2 场原文 + 最多 20 条回想”控制；以后需要对更早的回想再做摘要。
