# 技术设计：第一个可用版本

> 状态：**草案，待用户复核**（2026-10-09）。产品含义以 [requires.md](requires.md) 与 [PROJECT_BIBLE.md](PROJECT_BIBLE.md) 为准，本文只回答“怎么做”。
> 范围是第一刀纵切；本文未列入“本刀做”的功能都在 [§12 留位](#12-留位这一刀不做的事)里留了位置。拿不准而自己定的事集中在 [§13 待用户复核](#13-待用户复核)。

## 1. 目标

在本机跑通一条完整的路径：

1. 一句话创作世界与人物 → 一页预览（可手改）→ 确认诞生；
2. 选附身谁、写一句开场 → 叙事者开场 → 一场双人戏（说 / 做 / 静候，流式气泡，长按看心声，由用户结束）；
3. 散场后经历落库，异步为每个在场人物生成回想；第二场能接上第一场；
4. 技术失败按技术失败呈现，可以重试；人物的选择不重抽（圣经 §3.4）。

设计的两个主轴来自验证结论（[core-validation.md](../plan/core-validation.md) §8）：

- **延迟是首要风险**：单次调用常见 2–30 秒，偶发超过 100 秒。所以人物要尽快开口、边生成边推送，叙事者不挡在人物前面。
- **模型会换，Prompt 会改**：框架薄，模型与服务商可配置，每次调用都记账，Prompt 有快照。

## 2. 形态

```text
浏览器 PWA (React + Vite + TS)
   │  HTTPS/HTTP：JSON；一场戏的每一轮用 SSE（POST + 流式响应）
   ▼
Java 服务 (JDK 25, Spring Boot, Spring MVC 阻塞式 + 虚拟线程)
   ├─ web      控制器、登录、SSE 推送
   ├─ scene    一场戏：轮次、可见性、上下文装配
   ├─ memory   散场后的回想
   ├─ creation 一句话创作
   ├─ model    模型网关：OpenRouter 客户端、记账、预算、失败分类
   └─ prompt   所有 Prompt 原文（带快照测试）
   │  JDBC
   ▼
PostgreSQL（所有数据按用户隔离）          OpenRouter（OpenAI 兼容接口）
```

- 一个 Java 进程，一个数据库，一个静态客户端目录；生产式运行时由 Java 服务同源托管客户端，避免跨域与 cookie 问题。开发时 Vite dev server 代理 `/api`。
- 阻塞式 + 虚拟线程：一场戏的一轮是“同一人物串行、不同调用可并发”的小并发，阻塞代码最容易读、最容易调试；响应式栈的收益在这个量级用不上（见 [x-chat-ai-lessons](reference/x-chat-ai-lessons.md) §4）。
- 不引入消息队列、缓存、向量库。散场后的回想用进程内虚拟线程异步执行，丢了可以在下一场开始时补做（见 §7）。

### 工程布局

server/    Maven 工程（Java 25）
client/    Vite + React + TypeScript
docker-compose.yml   本机 PostgreSQL
scripts/   启动脚本

## 3. 数据

### 3.1 隔离

- 所有业务表都有 `user_id`，数据库层面用**复合外键** `(user_id, x_id)` 指向父表的 `(user_id, id)`，保证子行不可能挂到别的用户的父行上。
- 所有查询都带 `user_id`，用户身份只来自登录会话，不来自请求体。
- 第一版只有一个本地账号，但表结构与代码路径已经按多用户写。

### 3.2 表

| 表 | 内容 | 可变？ |
| --- | --- | --- |
| `users`、`sessions` | 账号（口令哈希）、登录会话 | 会话可过期 |
| `settings` | 每用户的模型配置覆盖项（角色 → 模型 / 推理设置） | 可改 |
| `worlds` | 名称、公共设定、只有叙事者知道的设定 | 诞生后不改 |
| `characters` | 故乡世界、姓名、叙述式档案 | 诞生后不改（圣经 §3.2） |
| `scenes` | 世界、被附身的人物、基调、开场处境、状态（进行中 / 已结束） | 只改状态与结束时间 |
| `scene_characters` | 在场人物及角色（附身 / AI） | 不改 |
| `scene_events` | **一场戏里发生的事**：叙事、用户的说 / 做 / 静候、人物的行 / 说 / 心声、技术失败、失败已解决的标记 | **只追加** |
| `recollections` | 散场后每个在场人物的回想与对在场人物的看法 | 是整理产物，可重新生成 |
| `model_calls` | 每次模型调用：用途、模型、服务商、费用、耗时、首字耗时、token、推理 token、结果、错误 | 只追加 |

### 3.3 一场戏里发生的事：只追加，不改写

`scene_events` 每行一件事，`seq` 在场内递增，写入后不改：

| `kind` | 含义 | 人物能感知吗 |
| --- | --- | --- |
| `narration` | 叙事者的文字（开场、裁定、环境、收尾） | 公开，在场者都能 |
| `user` | 被附身人物的说 / 做 / 静候（用户的原文） | 公开 |
| `character` | AI 人物的 `beats`（行 / 说，按先后）、`inner`（心声）、`silent`（只有心声，既不说也不做） | 行与说公开；心声只有本人 |
| `failure` | 某一步技术失败（`step`：叙事者 / 哪个人物） | 无，不属于世界 |
| `resolved` | 某个失败已被重试解决（`ref_seq`） | 无 |

**可见性规则**（从原型移植，`Visibility`）：人物看到什么，由这条规则从事件里筛出，规则是一个纯函数 `visible(event, viewer)`：

- `narration`、`user`、`character` 的公开部分对在场的所有人可见；
- `inner` 只对说话人本人可见；
- `failure`、`resolved` 对任何人物都不可见。

同一场里在场者没有变化（双人戏），所以规则不需要“在场区间”。群戏里人物会离开、路人会进出，那时每个事件要记录“当时在场者”，规则里加一条；这是 [§12](#12-留位这一刀不做的事) 的留位之一。

事件不存“谁看到了”，只存发生了什么。散场后“成为各人的经历”也不复制数据：各人的经历就是按可见性规则对 `scene_events` 的视图。

### 3.4 回想

`recollections(user_id, character_id, scene_id, status, memory, views jsonb)`：

- `memory`：用该人物自己的口吻写的这场戏的回想。
- `views`：`{对方姓名: 现在怎么看 TA}`，这就是“与在场人物的关系”的当前状态。取某人对某人的看法，就是该人物最近一条带有这个对方的回想。
- 它是整理产物而不是原始经历：可以重新生成，不影响事实。原始经历永远在 `scene_events` 里。

## 4. 模型接入

### 4.1 网关

```text
ChatModel（接口：一次补全，可选逐段回调）
  ├─ OpenRouterChatModel   java.net.http.HttpClient，SSE 流式，解析 usage / provider
  └─ FakeChatModel         确定性替身（测试与 fake 模式）
ModelGateway
  - 预算检查 → 调用 → 写 model_calls
  - 分类失败：可重试（429、5xx、网络抖动）/ 服务商拒绝 / 致命（401、402）
  - 校验：截断、空响应、格式不合规 → 同样记为技术失败
  - 每次调用最多重试一次（可重试的先退避几秒）；仍失败就把技术失败交给调用方
```

不引入 Spring AI 或 LangChain4j：只有一个 OpenAI 兼容端点，一个 `HttpClient` 加两百行就够，而且流式、服务商路由、费用字段都需要精确控制。

### 4.2 配置

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 人物 / 叙事者（开场与收尾）/ 叙事者（逐轮决定）/ 创作 / 回想 各自的模型 | `deepseek/deepseek-v4.1-flash` | 环境变量设默认；设置页写入 `settings` 后随时生效，不用重启 |
| 推理设置 | 模型默认（开推理）；**叙事者逐轮决定固定默认关闭** | 可写 `off`、`low`、`medium`、`high`。逐轮决定是一行 `叙事：…` 的短输出，冒烟测试里开着推理时它有一次花了 20 秒，拖住了下一轮；关闭后中位数约 1 秒（见 §13） |
| 首选服务商 | `Parasail` | 对应 OpenRouter 的 `provider.order`，`allow_fallbacks: true`：首选故障时回退，不是只用首选 |
| 费用硬上限 | 无 | `LYNG_BUDGET_USD`，设了就按 `model_calls` 累计费用在每次调用前检查，达到就停并报“已达费用上限” |

- 首选服务商选 `Parasail`（fp8），依据是思考强度实验里 345 次调用的服务商记录：它 21 次调用中位数 2.1 秒、0 次失败，且量化精度明确标为 fp8（`Together` 41 次、中位数 1.4 秒、0 失败，但精度未标明）。模型出品方 `DeepSeek` 本来是更自然的选择，但冒烟测试时发现它被账号设置挡住了：OpenRouter 的账号隐私设置禁止“会拿付费请求做训练”的服务商，路由时报 `Paid model training violation (account settings)`。放开这项设置是账号隐私层面的取舍，留给用户决定（见 §13）。
- 每次调用记录**实际**服务商（响应里的 `provider`），而不是配置的首选；回退发生时能看出来。

### 4.3 记账

`model_calls` 每次调用（含失败、含重试的每一次尝试）一行：用途（人物 / 叙事者 / 创作 / 回想）、模型、服务商、费用（来自接口返回的 `usage.cost`）、总耗时、首字耗时、输入 / 输出 / 推理 token、`finish_reason`、结果（成功 / 技术失败的类别）。接口没返回费用的成功响应视为故障：报错，不当成 0 费用。

## 5. 一场戏的调用链

### 5.1 开场

用户选好世界、被附身的人物、对方（在场的 AI 人物）、基调（日常相处 / 冒险）并写下开场处境 → `POST /api/scenes` 创建 `scenes` → 客户端立刻调用 `/open`：先补做缺失的回想（§7.2），再由叙事者写开场（一两句，只使用用户给的处境，也看得到上一场的公开经过）→ 记为 `narration`。叙事者开场失败：这一场停在“等待开场”，显示技术失败，可以重试。

### 5.2 一轮

用户每次提交一个动作：**说**、**做**或**静候**。服务端把它记为 `user` 事件，然后：

```text
说 / 静候:
   ┌─ 人物生成（流式，逐个气泡推给客户端）──────────┐
   │                                                 ├─ 都结束后写入事件，顺序：人物 → 叙事
   └─ 叙事者幕后决定“要不要出声”（并发，不挡人物）──┘

做:
   叙事者裁定（先出声，结果不确定的动作才写一两句；递茶、牵手这类写“无”）
      └─ 人物生成（流式；看得到刚写出的裁定）
```

要点：

- **双人戏不做调度**（圣经 §4.4）：每一轮 AI 人物都接戏，接不接由 TA 决定（可以只有心声）。
- **叙事者不挡在人物前面**：“说 / 静候”时人物与叙事者并发，叙事者看到的是人物回应之前的处境，所以它的出声（若有）排在人物之后。只有“做”的结果需要裁定时叙事者才先出声，因为人物的反应取决于结果。
- 叙事者每轮的输出是一行 `叙事：…`（无则 `叙事：无`），即原型的双人戏格式。叙事者的调用是短输出，不流式。
- 同一场同一时刻只允许一轮在跑（场内锁）；客户端断开后这一轮在服务端继续跑完并落库，刷新后从数据库恢复。
- 费用：每轮 2 次调用（人物 + 叙事者），都是短输出；记账不追加任何同步调用。

### 5.3 流式与标记

人物的输出沿用原型的标记（从原型移植，`Markup`）：

```text
陆雪琪（行）：她抬眼看了他一下。
陆雪琪（说）：你来了。
陆雪琪（心声）：（没说出口的话）
```

- 流式解析器按行累积；遇到下一个带标签的行，就把前一个完成的“行 / 说”作为一个气泡推送；流结束时校验整体：心声恰好一行且在最后、没有写别人的言行、没有标签之外的文字。
- 推送的气泡在客户端是**暂定**的。整体校验通过后服务端写入事件并发 `commit`；校验失败（截断、缺心声等）则发 `retract`，客户端撤掉这个人物暂定的气泡，服务端自动重试一次，重试仍失败才记为技术失败。写了别人的言行这类逐行可判的错误，在流中立即中止并重试，不会推送出去。
- **心声默认隐藏**：随这个人物的事件一起下发，客户端长按气泡才显示。

### 5.4 结束

用户点“结束这场戏” → 叙事者收尾（一两句，留一个想继续的理由）→ `scenes.status = 已结束` → 异步生成回想（§7）。收尾失败：可以重试，也可以“直接结束”（不写收尾）。

## 6. 失败

| 情形 | 处理 |
| --- | --- |
| 429、5xx、网络错误、空响应、截断、格式不合规 | 自动重试一次（限流类先退避几秒）；仍失败记 `failure` 事件，戏停在这一步，用户点“重试”重做**这一步**，成功后记 `resolved` |
| 服务商拒绝（内容审核） | 记 `failure`，说明是服务商拒绝，不自动重试；用户可以重试或换模型 |
| 401 / 402 / 费用上限 | 记 `failure`，写明原因，不重试 |
| 人物这一轮失败 | 不记成“没有开口”，也不进入任何人物的感知；重试时人物重新生成这一轮的回应——这不是重抽“人物的选择”，因为这一轮从未有过成功的回应 |

**不能重抽的是已经说出口的。** 已落库的 `character` 事件没有任何“重抽”接口；重试只重做失败的那一步，且条件与第一次相同（人物重试时看到的事件，只到失败发生的那一刻为止）。客户端暂定气泡被撤回，只会出现在技术失败之后，不是人物的选择。

用户自己的话在人物回应之前可以撤回重写（圣经 §3.4）：**这一刀不做撤回**，只做重试，见 §12。

## 7. 记忆

### 7.1 原始经历

`scene_events` 永久保存，每条标明说话人与对象。人物的经历是按可见性规则对它的视图。

### 7.2 回想

散场（`end`）后，为每个在场人物各发起一次模型调用（含被附身的人物：做过的算数，怎么看待那一刻由 TA 自己，圣经 §2.3），异步、互不阻塞：

- 输入：该人物的档案，这一场里 TA 的所见所闻（含 TA 自己的心声），TA 此前对在场其他人的看法。
- 输出：两类带标签的行：`回想：…`（第一人称，几句话）和 `看待<姓名>：…`（一两句）。
- 失败：`recollections.status = failed`，记录原因；**下一场开始时**，对涉及的人物补做缺失或失败的回想（先等进行中的，再补做）。所以丢失、失败都不会丢连续性，最多多等一次调用。
- 人物页展示“TA 记得的事”与“TA 怎么看某人”，只读（圣经 §6.1）。

### 7.3 人物开口时看到什么

人物生成时，上下文按如下顺序装配：

1. 系统：身份与分寸、**世界的公共部分**、**档案**、内容尺度；
2. **与在场人物的关系**：TA 此前对在场每个人的看法（`views`）；
3. **更早场景的回想**：最近 `recent` 场之外、TA 经历过的每场的回想，由旧到新；
4. **近期场景的原文**：最近 `recent`（默认 2）场已结束的场景里 TA 感知到的原文，标明说话人，是感知材料而不是对话历史；
5. **这一场到现在**的感知材料（按可见性规则；自己的心声标为“你自己”）；
6. 本轮指令与输出格式。

旧台词始终是“感知材料”，不作为 assistant 历史回放（教训见 [x-chat-ai-lessons](reference/x-chat-ai-lessons.md) §2）。叙事者看到：两份世界设定、在场人物的档案、最近一场已结束场景的公开原文、本场的开场处境与公开事件，**看不到**任何人的心声与回想。

## 8. 创作

1. 用户输入一句话（可选：已有世界，则只生成人物）。
2. 一次模型调用，输出带标签的纯文本（不用 JSON，教训同上）：`【世界名】`、`【世界·公开】`、`【世界·只有叙事者知道】`、若干 `【人物】姓名` + 叙述式档案。Prompt 规定“描述里写了几个人物就生成几个，不自行添加”。
3. 服务端解析为草稿返回客户端（不落库）；格式不合规按技术失败处理，可重试。
4. 客户端展示一页预览：世界一段，每人一张卡，全部可手改；确认后 `POST` 草稿，服务端在一个事务里创建世界与人物（“诞生”）。

## 9. 接口

JSON；除登录外都需要会话。一场戏的每个“会跑模型的动作”用 **POST 返回 `text/event-stream`**，客户端用 `fetch` 读流（`EventSource` 只支持 GET）。

| 方法与路径 | 作用 |
| --- | --- |
| `POST /api/login`、`POST /api/logout`、`GET /api/me` | 登录与会话（HttpOnly cookie） |
| `GET /api/worlds`、`GET /api/characters`、`GET /api/characters/{id}` | 世界与人物；人物详情含档案、记得的事、对某人的看法 |
| `POST /api/creation/draft` | 一句话 → 草稿（JSON） |
| `POST /api/creation/confirm` | 确认诞生 |
| `GET /api/scenes`、`GET /api/scenes/{id}` | 场景列表；一场戏的全部事件与状态（刷新恢复用） |
| `POST /api/scenes` | 创建一场戏（返回场景 id） |
| `POST /api/scenes/{id}/open` | 叙事者开场（SSE） |
| `POST /api/scenes/{id}/act` | 提交说 / 做 / 静候，跑一轮（SSE） |
| `POST /api/scenes/{id}/retry` | 重做这一场最近一轮里失败的步骤（SSE） |
| `POST /api/scenes/{id}/end` | 叙事者收尾并结束（SSE）；`closing=false` 直接结束 |
| `GET/PUT /api/settings` | 各角色（character / narrator / narrator_round / creation / recall）的模型与推理设置 |
| `GET /api/usage` | 累计费用与最近的调用记录（含服务商与耗时） |

SSE 事件：`user`（已落库的用户事件）、`bubble`（暂定气泡）、`retract`（撤回某人物的暂定气泡）、`commit`（人物事件落库）、`narration`、`failure`、`resolved`、`done`、`error`（传输层出错）。

## 10. 客户端

React + Vite + TypeScript，PWA（manifest + 极简 service worker，可装到手机桌面）。

- 页面：登录；首页（人物、进行中和最近的场景）；创作（一句话 → 预览 → 确认）；开场；一场戏；人物页；设置。
- 一场戏：气泡说话、动作成行、叙事者居中；被附身人物的气泡在右侧；**长按**人物气泡显示心声；底部输入框与“说 / 做”开关、“静候”、“结束这场戏”；技术失败显示在失败的位置，带“重试”。
- 风格按圣经 §4.3：像 iMessage，纯色，无渐变、光晕、闪烁动画、多余状态标签与徽章；“正在输入”只用最朴素的省略号。
- 状态管理只用 React 自带的 state / reducer；SSE 事件交给一个纯函数 reducer，便于单测。

## 11. 认证

- 单个本地账号：`LYNG_USER`（默认 `me`）、`LYNG_PASSWORD`（必填，只从环境读；未设置则启动失败并提示）。启动时把环境口令同步成 BCrypt 哈希。
- 登录发随机会话令牌，库里只存哈希，cookie 为 HttpOnly、SameSite=Lax。第一版不做限流与多账号注册。
- 只面向本机使用；对外部署前要补 HTTPS、登录限流与 CSRF 令牌（部署本身属于硬线，不在这一刀）。

## 14. 测试

- **Prompt 快照**：每个 Prompt 一份快照（`server/src/test/resources/snapshots`）。移植的叙事者 Prompt 与原型快照逐字节一致（平行测试）；改 Prompt 必须同时更新快照。
- **标记与流式解析**：从原型移植格式用例，新增逐字符 / 乱序分片喂入的流式用例。
- **可见性**：心声只有本人可见，失败不进感知，其他人看不到本人的心声。
- **人物行为（确定性替身）**：一轮的顺序（说 → 人物先于叙事；做 → 叙事先于人物）、静候记为“没有开口”、技术失败不变成沉默、重试只重做失败的步骤、已落库的人物回应不被改动、被附身的人物不在调度里、散场生成回想、第二场的 Prompt 里有第一场的内容。
- **集成**：嵌入式 PostgreSQL + 真实 HTTP + 替身模型，自动走完“创作 → 第一场 → 结束 → 第二场”，并断言按用户隔离。
- **客户端**：SSE 解析与事件 reducer 的单测；构建通过。
- 真实模型只用于冒烟测试，单独授权、单独记账。

## 15. 已知风险

- **延迟**：流式与并发缓解，但服务商波动仍会出现长尾；`model_calls` 提供事后分析依据。
- **叙事者出声的质量**：并发让叙事者看不到人物的回应，可能出现“叙事重复人物刚做的事”；需要真实使用后评估。
- **回想质量**：没有盲测；它决定第 3 场起的连续性。
- **上下文增长**：回想与近期原文随场次增长；第一版靠 `recent` 与回想条数上限控制，后续需要更早回想的再摘要。
