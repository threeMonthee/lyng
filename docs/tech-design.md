# 技术设计

> 状态：2026-10-16 第一版。产品含义以 [requires.md](requires.md) 与 [PROJECT_BIBLE.md](PROJECT_BIBLE.md) 为准，本文只回答“怎么做”。

## 1. 决定一览

| # | 决定 | 依据 |
| --- | --- | --- |
| 1 | 一个 Java 进程 + 一个 PostgreSQL；构建好的网页由 Java 同源托管 | 单人自用、低并发；少一层就少一个出错的地方 |
| 2 | Spring MVC 阻塞式 + 虚拟线程；会跑模型的接口用 POST 返回 `text/event-stream` | 用户要求阻塞式；x-chat-ai 的响应式栈对可读性与调试代价大 |
| 3 | 数据访问用 Spring `JdbcClient` 写 SQL；`schema.sql` 启动时建表（`IF NOT EXISTS`），不做迁移 | 表少、SQL 直观；没有旧数据要兼容，改表时重建库 |
| 4 | 人物每次开口是**一次**生成，输出验证过的标记格式（行 / 说 / 心声）；可调用一个工具 `recall` 翻看更早的经历 | 盲测验证过的写法；x-chat-ai 两段式与 JSON 交接让人物变冷 |
| 5 | **整理内心**单独一次生成，在一场戏散场后、离开私聊或私聊攒够一批后异步进行；开口前补齐缺的整理 | 不压在表演上（x-chat-ai 教训：每轮同步记账占 79% 等待） |
| 6 | 亲历原文按“谁看到了”复制成每个人物自己的**痕迹**，带向量；召回 = 最近 + 向量相似 | 每个人物的认知天然隔离；SQL 一句话召回 |
| 7 | 所有模型调用经 `Gateway`：一次**运行**（run）可有多次尝试和工具轮次；运行与尝试都落库，供幕后观察 | 观察与记账同源，不另建链路追踪 |
| 8 | 失败不进经历：场景与私聊上记“还剩哪几步”，重试从剩下那一步接着做 | 失败不属于世界；服务重启后也能接着做 |
| 9 | 流式按行推送：一行写完就推，整次生成校验通过才落库；校验失败页面收回临时行 | 首行比整轮早几秒出现 |
| 10 | 前端 React + TypeScript + Vite + Tailwind + shadcn/ui 风格组件（Radix），一套响应式布局 | AI 最熟的组合；用户只看体验 |
| 11 | 不做登录；所有表带 `user_id`（现阶段固定 `me`）；服务默认只监听本机 | 现阶段不部署；不堵 C 端 |

## 2. 形态

```text
浏览器（React，响应式：手机底部导航，电脑侧栏）
   │  JSON；跑模型的动作 → text/event-stream
   ▼
Java 25 · Spring Boot（MVC 阻塞式 + 虚拟线程）
   ├─ model    Gateway：OpenRouter 流式客户端、工具轮次、重试、预算、记账、运行记录；百炼 Embedding；确定性替身
   ├─ mind     人物的上下文、开口、召回、整理内心、标记解析
   ├─ scene    一场戏：步骤、叙事者、同意检查
   ├─ chat     私聊：发送、继续、主动、未读
   ├─ create   一念生：追问、写稿、局部改、一致性检查、诞生
   ├─ store    SQL
   └─ web      接口、SSE、静态页面
   ▼
PostgreSQL + pgvector             OpenRouter · 百炼
```

## 3. 数据

所有表带 `user_id`。主键用 UUID（`lines`、`messages`、`traces` 用自增 id 保证顺序）。

| 表 | 内容 | 变化 |
| --- | --- | --- |
| `settings` | 内容尺度、费用上限 | 可改 |
| `worlds` | 名字、公开设定、只有叙事者知道的事 | 诞生后不改 |
| `characters` | 世界、姓名、出生档案（叙述，带【小标题】） | 诞生后不改 |
| `selves` | 如今的自我，每次改变追加一行，最新一行为当前 | 只追加 |
| `views` | 某人对另一人的看法，每次追加完整的当前看法 | 只追加 |
| `concerns` | 牵挂：内容、关于谁、状态（活跃 / 背景 / 了结）、了结说明 | 状态会变 |
| `memories` | 记忆：发生了什么、个人意义、涉及的人、来源（戏 / 私聊）、向量 | 只追加 |
| `scenes` | 序号、世界、基调、尺度、开场处境、附身 / 跟随、状态、**剩余步骤**、失败原因 | 会变 |
| `scene_cast` | 一场戏的在场人物 | 建场时定 |
| `lines` | 一场戏里发生的事，一行一件：叙事 / 说 / 行 / 没有开口 / 心声 / 收尾 | 只追加 |
| `conversations` | 两个人物的私聊（a < b）、你上次附身的一方、剩余步骤、失败、整理到哪一条 | 会变 |
| `messages` | 私聊里的话：说 / 心声；是否出自你；是否已读 | 只追加（已读会变） |
| `traces` | 每个人物的亲历痕迹：从 `lines` / `messages` 按可见性复制、写成感知材料的一行、向量 | 只追加 |
| `consolidations` | 每个人物待整理的来源（某场戏 / 某段私聊到某条）与状态 | 会变 |
| `runs` | 一次运行：用途、关联的人物 / 戏 / 私聊、完整请求、输出、思考、工具调用、解析结果、保存了什么、状态 | 只追加（结束时补全） |
| `model_calls` | 每次尝试：模型、服务商、费用、耗时、首字、token、结果、错误 | 只追加 |
| `drafts` | 一念生草稿（JSON）：描述、追问与回答、世界、人物、状态 | 可改，诞生后封存 |

**可见性**：叙事、说、行、没有开口对在场所有人可见；心声只有本人可见。私聊双方都看到说的话，心声只有本人。`by_user` 只用于界面，写进人物上下文时与其他行完全一样。

## 4. 模型

### 4.1 Gateway

```text
run(用途, 关联对象, 消息, 工具?, 解析器, 流式回调) → 解析结果 + runId
  预算检查 → 写 runs（开始）
  尝试 1..2：
    调用（流式）→ 工具调用？执行工具、追加结果、再调用（最多 3 轮）
    空响应 / 截断 / 格式不合规 / 429 / 5xx / 网络 → 记一次失败尝试，重试
    服务商拒绝 / 密钥 / 费用上限 → 不重试
  成功：写 runs（输出、思考、工具、解析结果）
  失败：写 runs（失败原因），抛 CallFailure
```

- 每种用途一个模型配置（环境变量），默认都是 `deepseek/deepseek-v4.1-flash` 开推理；叙事者逐轮决定与同意检查默认关推理（它们在人物之前串行）。
- 首选服务商 `Parasail`，允许回退；每次尝试记录实际服务商。
- `FakeModel` 是确定性替身：按用途与输入生成合规的输出，测试与 `--fake` 模式用。`ScriptedModel`（测试）按脚本返回，可注入失败。

### 4.2 Embedding

`Embedder.embed(texts, query?)`：百炼 `qwen3.7-text-embedding`（维度可配，默认 1024）；`FakeEmbedder` 用字符二元组哈希成固定维度向量，测试里相似的句子真的相近。向量列不限维度，不建索引（个人规模，精确扫描足够）。索引失败只影响召回，原文照存，下次补。

## 5. 人物开口

### 5.1 上下文

```text
system：你是谁 · 世界（公开）· 出生档案 · 如今的自我 · 你眼中的他们 · 你放不下的事（活跃牵挂）· 你记得的（召回）· 分寸
user：  （一场戏）这一场到现在的感知材料 · 轮到你 · 篇幅 · 写法
        （私聊）  你和 TA 最近的私聊 · 此刻（新话 / 继续 / 你回来了）· 写法
```

- **召回**：用最近几行感知材料做查询向量，在这个人物的 `memories` 与 `traces` 里找最相近的若干条（排除已经在上下文里的），按时间排好，标明来源（第几场 / 和谁的私聊）。另附最近 3 条记忆。
- **工具 `recall(query)`**：人物觉得不够时自己翻，返回最多 6 条，带来源。
- 感知材料一律写成标明说话人的行，放进 user 消息，不作为对话历史回放。

### 5.2 写法

一场戏（盲测验证过的格式）：

```text
陆雪琪（行）：……
陆雪琪（说）：……
陆雪琪（心声）：……   ← 必写，一行，最后
```

私聊没有（行）。只写心声 = 此刻不说也不做（私聊里就是有动机的沉默）。写了别人的言行、标记外有文字、缺心声，都是格式不合规。

## 6. 整理内心

散场、离开私聊、私聊攒够 24 条新话、或人物开口前发现有未整理的来源时，排一次整理（后台虚拟线程，同一人物串行）。

```text
system：你是谁 · 世界 · 出生档案 · 如今的自我
user：  你此前怎么看他们 · 你放不下的事（带编号）· 这段经历（感知材料）· 怎么写

【记忆】发生了什么（用“我”写，具体）
【意义】当时对我意味着什么
【看法·陆雪琪】现在怎么看她（完整的当前看法）
【牵挂】新的牵挂（可写“关于：某人”）
【了结·2】怎么了结的
【放下·3】
【自我】改变后的完整自我理解
```

每个标签可以出现零次或多次（【意义】紧跟【记忆】）；什么都没有就写【无】。一次整理在一个事务里保存，`runs` 记下保存了什么。

## 7. 一场戏

步骤：`opening`、`narrator`、某个人物 id、`closing`。场景记“还剩哪几步”。

```text
建场景        → 剩 [opening]
用户动作      → （成人向的“做”先过同意检查）写下那一行 → 剩 [narrator]
narrator 成功 → 写叙事（若有）→ 剩 [被点到的人物…]（双人戏：那个 AI 人物）
人物成功      → 写 TA 的行 → 去掉这一步
closing 成功  → 写收尾 → 结束 → 排整理
```

- 每一步成功就落库并推进；失败停在这一步。重试从剩下第一步接着做，人物看到的只到失败那一刻为止。
- 同一场同一时刻只跑一件事；有未完成步骤时不能做新动作、不能切换身份。
- 叙事者 Prompt 与人物 Prompt 的表演部分沿用盲测验证过的版本（[lessons](reference/lessons.md) §5），新增的只有内心各层与召回。

## 8. 私聊

- 一对人物一段私聊。打开私聊时选你附身哪一方（默认上次那一方）。
- 发送：写下你的话 → 剩 [对方] → 对方开口（流式）→ 写下说的话与心声。只写心声就是沉默。
- 继续：剩 [对方]，不写新话。
- 主动：`POST /api/presence`（页面回到前台、距上次超过 30 分钟时调用）。对每段私聊：你上次附身的一方是 P，对方 Q 有关于 P 的活跃牵挂，最后一条话在 30 分钟前，Q 不在进行中的戏里 → Q 得到一次主动机会（每次最多 3 个，后台串行）。写出的话为未读。
- 正在进行中的戏里的人物不能私聊（同一时刻只在一处）。

## 9. 一念生

```text
POST /drafts            一句话 →（追问）0–3 个问题，每题带推荐与选项
POST /drafts/:id/write  回答 → 写稿（流式显示写到了谁）
PUT  /drafts/:id        手改
POST /drafts/:id/revise 指定一段 + 要求 → AI 只改这一段，返回建议，采用后才替换
POST /drafts/:id/check  一致性检查 → 冲突列表（可能为空）
POST /drafts/:id/birth  诞生：一个事务写世界、人物、初始看法、初始牵挂
DELETE /drafts/:id      结束这次创作
```

草稿写法用标记（【世界名】【世界·公开】【世界·只有叙事者知道】【人物】【档案】【看法·某人】【牵挂】），解析成 JSON 存进 `drafts`。

## 10. 接口与流

- JSON 接口在 `/api`。错误统一为 `{ "error": "人能读懂的一句话" }` 与合适的状态码。
- SSE 事件：`status`（正在做哪一步、谁）、`draft`（一行临时内容）、`discard`（这次尝试作废，收回临时行）、`saved`（这一步落库的行）、`failed`（技术失败与原因）、`done`。客户端断开后服务端照常跑完并落库，刷新后从数据库恢复；页面看到 `running` 时轮询。

## 11. 前端

- 路由：首页（世界与最近）、一念生、世界页、开一场、一场戏、消息、私聊、人物主页（关于 / 牵挂 / 记忆 / 看法 / 经历）、幕后、设置与用量。
- 手机宽度用底部导航与全屏页面，电脑用左侧栏与居中内容列。
- 视觉：像 iMessage / 微信一样克制；不用渐变、光晕、闪烁动画、多余的状态标签。人物原文用衬线字体，界面用无衬线。浅色与深色都要好看。
- 每个页面都有加载、空、失败、等待、中断的正式状态。

## 12. 测试

- 服务端：标记解析、Prompt 快照、Gateway（重试、工具轮次、预算、记账）、一场戏与私聊的行为测试（脚本化替身）、整理内心、召回、一念生全流程、接口流程。测试连本机 PostgreSQL 的 `lyng_test` 库。
- 客户端：类型检查、组件与流解析的单元测试；用替身启动整套服务，在电脑与手机宽度走查截图。
- 真实模型只用于冒烟，需要在对话里单独授权场景与预算。
