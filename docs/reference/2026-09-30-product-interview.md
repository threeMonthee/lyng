# 2026-09-30 产品访谈与重构建议

> 参考资料，不是约束。来自前身项目 x-chat-ai 的一次产品访谈（原件：`x-chat-ai/plan/proposals/2026-09-30-product-restructure.md`）。第 1 节是用户答复，属于已表达的意图；第 2–3 节是当时的诊断与建议，尚未确认。第 3 节中“阶段 0–3”是基于旧代码渐进改造的路线，已被 0→1 重写取代，只保留其产品内容。

## 1. 访谈结论

| 维度 | 用户答复 |
| --- | --- |
| 定位 | 主要自己用 / 作品，不追增长 |
| 核心体验 | 与喜爱的角色长期相处；情感陪伴与被在意；沉浸式剧情 / 扮演。窥见内心不是首要卖点 |
| 最不满意 | 聊天不够有人味：创建的诛仙陆雪琪为维护设定不承认错误，爱是冰冷机械的；行动只能靠括号表达，很累；UI AI 味太浓，不够简单精致 |
| 改动边界 | 原则也可以重新审视 |
| 交流形态 | 最初选“消息与见面按情境切换”，随后收回：**统一为见面，不需要消息** |
| “真的爱” | 会软化、认错、让步；有情绪起伏和脆弱；主动、会想你 |
| 观察层 | 改造成轻量的“心声” |
| 多身份 | 原本用于从多个身份角度窥测角色内心、检验表达是否合理；用户提出“身份是不是也就是角色，用户可以自由接管不同 AI 角色” |
| 接管 | 完整接管与交还 |
| 离线 | 离线就静止；回到 App 时的行为暂不改 |
| 模型 | 效果优先，可换更强模型（含海外） |
| UI 参照 | iMessage / 微信的克制；暂无更具体参照 |
| 组织单位 | 人物是活着的人，可以进入一个世界 / 故事 |
| 世界推动 | AI 叙事者 + 用户定开场 |
| 跨世界 | 跨世界连续（穿越） |
| 世界影响 | 用户暂时跳过 |
| 真实度 | 真实的人会为在乎的人改变 |
| 创作起点 | 保留预览确认，压缩步骤 |

## 2. 诊断

- **表达模型“没有心”**：人物回复先由私密心智输出 JSON，其中 `publicIntent` 是一句意图；公开表达模型只接收姓名、表达倾向、收件人和公开意图，看不到历史、关系与情绪。爱被压缩成意图，再由不了解关系的模型转述。
- **心智 Prompt 以记账为主**：ID、developments、correction、schema、牵挂上限等占主体，关于“做一个人”的只有几句；首句强调可以拒绝、反驳、怀疑、隐瞒、说谎，并强调对话不是命令或客观真相，模型因此把守住设定当作首要任务。
- **人设是标签表**：`"性情":["内敛","细心"]` 一类标签让模型演出符号化的冷，演不出外冷内热。
- **行动难表达**：界面是私聊 IM，内容却是面对面古风人物，形态本身未定，动作只能挤进括号。
- **上手链路长**：创建人物、创建身份、初见确认约 10 步以上才开口；概念约 8–10 个。

## 3. 建议方案

### 3.1 温度（不改结构，最先做）

1. 合并两段式：同一次调用看到全部上下文并直接流式写出言行；Memory / 自我 / 认识 / 牵挂等记账移到场景结束或每隔几轮的异步“回想”。
2. Prompt 重写：去掉对抗式开头，改为“活生生的人，对在乎的人会心软、会认错、会让步”；区分立场（可坚持）与事实错误（被证明就认）。
3. 人设从标签改为叙述：第一人称小传 + 外在与内心的反差 + 她在乎一个人时的样子 + 她如何和好。
4. 模型盲测：同一组陆雪琪场景（认错、吃醋、和好、主动、脆弱）横评候选模型，以主观盲评选型。需当前对话授权付费调用。

### 3.2 概念结构：约 10 个概念收敛为 4 个

| 新概念 | 含义 | 取代 |
| --- | --- | --- |
| 人物 | 活着的人，有档案与连续人生；由 AI 驱动或被用户接管 | Character + UserIdentity、原型、主身份 |
| 世界 | 设定（时代、地理、规则、势力），可来自原作 | 原先冻结的 World |
| 场景 | 一次见面：世界、地点、时刻、在场人物；有开场与结束，结束后成为人物经历 | 永久 Conversation、Message |
| 叙事者 | 非人物；描写环境与路人、裁定行动结果 | 无 |

- 接管与交还：接管期间用户以该人物说过、做过的就是其亲历；交还后 AI 继承为“自己做过的事”；接管期间该人物 AI 心智不运行；人物不知道被接管。
- 跨世界：人物有故乡世界；进入他界即穿越，叙事者在开场交代如何到来，带着全部记忆，对新世界有限认知。
- 世界影响最小版：叙事者只做描写与裁定结果，结果记为世界事实（如“张小凡左臂受伤”）；不做数值、背包、任务。
- 删除：主身份、初见确认、消息页、未读、跨身份提示、人物 / 身份二分、逐消息心智过程入口。

### 3.3 见面：场景页

- 外壳如 iMessage 克制，正文如小说。
- 顶部场景条：地点 · 时刻 · 在场人物小头像。
- 正文：叙事者浅色居中无头像；人物言行合一成段、带姓名；用户靠右。
- 输入：单框 +「说 / 做」切换；“做”由叙事者润色为自然叙述并裁定结果。
- “继续”改为「静候」：仍只给一次机会，不强迫说话。
- 心声：长按人物段落看“此刻没说出口的”一两句，与该段同次生成，默认隐藏。完整运行记录收进开发者模式。

### 3.4 信息架构

- 首页「相处」：最近场景，点开即接续。
- 「人物」：大肖像卡；人物页只留立绘与一句话、「TA 记得的事」、「TA 怎么看某人」、与 TA 的场景。
- 「世界」：设定、此世界的人物、开新场景。
- 账户收进右上角。
- 去 AI 味：去掉渐变、光晕、墨晕、闪烁思考动画、多余状态标签与徽章；系统字体、单一强调色，肖像是唯一视觉主角；状态文案收成一个词。

### 3.5 创作：保留预览，约 12 步压到 4 步

1. 一句话描述（如“诛仙，青云大试后，陆雪琪”）。
2. AI 生成世界概要与相关人物，一致性自检只在冲突时提示。
3. 一页预览：世界一段 + 每人一卡；可手改，可让 AI 局部改。
4. 确认诞生 → 开第一场：选接管谁 + 一句话开场处境 → 叙事者开场 → 入场。

### 3.6 需修订的原则

| 条目 | 修订 |
| --- | --- |
| §1 最高原则 | 保留“还原真人”；去掉“真实优先于迎合”的对抗式表述，改为“不讨好，但会爱；会被在乎的人改变” |
| §7 UserIdentity | 并入人物；被接管时由用户负责，交还后由 AI 承接 |
| §9 永久 Conversation | 改为场景 + 关系 |
| §12 私密 / 公开两段式 | 改为一次生成 + 事后回想 |
| §3 / §19 World | 从冻结改为纳入（叙事者轻量版） |
| 保留 | 有限认知、连续人生、永久记忆、出生快照、人物不知道自己是虚构 |

### 3.7 分阶段路线

| 阶段 | 内容 | 理由 |
| --- | --- | --- |
| 0 温度 | Prompt 重写、单次生成、叙述式人设、模型盲测 | 最痛、最便宜，先验证人味 |
| 1 见面 | 场景页、叙事者、说 / 做、静候、心声；删消息体系 | 解决行动表达与 UI AI 味 |
| 2 人物统一 | 身份并入人物，接管交还；删主身份与初见 | 数据库可重建，无迁移负担 |
| 3 世界 | 世界实体、穿越、多人同场 | 范围最大，放最后 |

## 4. 待用户确认

1. 交还语义：接管期间的言行交还后算人物亲历，人物永远不知道被接管。
2. 多人同场：阶段 1–2 每场景只有用户 + 一个 AI 人物，路人由叙事者代演；群戏放阶段 3。
3. 起点：先做阶段 0，需授权付费调用的场景、预算与候选模型。

## 5. 访谈后的补充决定（同日）

- 产品形态变化较大，旧代码大部分无法支撑；决定 **0→1 重写**，新仓库为 `lyng`，x-chat-ai 只读参考，特别是真实模型实验。
- 顺序：先重写产品圣经与需求，再做核心体验验证，再定功能设计与技术架构，最后分阶段实现。
- 服务端：**继续使用 Java**，倾向去掉响应式编程，改为传统阻塞编程（JDK 25 虚拟线程 + Spring MVC + JDBC；流式经 SSE）。具体待技术设计确认。
