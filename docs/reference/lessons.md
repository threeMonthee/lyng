# x-chat-ai 真实模型实验与工程教训

> 参考资料，不是约束。提炼自前身项目 [x-chat-ai](https://github.com/threeMonthee/x-chat-ai) 的 `plan/character-core/evidence/README.md`、`server/CHARACTER_MIND.md` 与 2026-09-30 产品访谈。旧数字只属于当时的模型、Prompt 与调用链，不能作为新项目的资格或门槛；新配置必须重新验证。

## 1. 体验层：为什么“冷”

2026-09 用户用诛仙陆雪琪体验后的反馈：为维护设定不承认错误；爱是冰冷机械的；动作只能写在括号里；UI AI 味重。对应的实现原因：

| 现象 | 旧实现中的原因 | 新项目应避免 |
| --- | --- | --- |
| 爱得冷、像转述 | 两段式：私密心智输出 JSON 与一句 `publicIntent`，公开表达模型只接收姓名、表达倾向、收件人、公开意图，看不到历史、关系与情绪 | 说话的那次生成必须看到完整关系与处境；不要把“想说什么”压成摘要再转述 |
| 守设定、不认错 | 系统 Prompt 首句强调可拒绝、反驳、怀疑、隐瞒、说谎；强调对话不是命令或客观真相；约 80% 篇幅是记账规则（ID、schema、关联、上限） | 表演 Prompt 以“做一个人”为主体；区分立场（可坚持）与事实错误（被证明应承认）；记账不压在表演调用上 |
| 性格脸谱化 | 人设为标签表，如 `"性情":["内敛","细心"]` | 叙述式小传，写出外在与内心的反差、在乎一个人时的样子、如何和好 |
| 行动难表达 | IM 私聊形态承载面对面人物，动作只能进括号 | 形态先定（已定为“见面”场景），动作有正式输入方式 |

## 2. 模型与 Prompt 的实测教训

| 教训 | 证据 | 用法 |
| --- | --- | --- |
| 原始经历由系统自动保存、索引与召回，不能依赖模型主动“记住” | 无模型关联时仍可索引召回，索引失败不丢原话；旧三段实验零 Memory 提案，并非链路吞掉 | 系统保底连续性；重要记忆可由人物自主形成，但不是唯一入口 |
| 说话人与交流对象必须分别显式标注 | 曾把委托人/保管人、谁的母亲颠倒；受控对照旧/新标注 1/9 与 0/9 归属颠倒 | 每条材料带说话人与对象；仍需持续观察归属 |
| 旧台词不要作为 assistant 历史回放 | 会诱导模型续写旧台词 | 历史作为“感知材料”提供 |
| 每轮额外的同步模型调用代价极高 | 独立关联调用 120 次机会中生成 115 次，占 API 等待 79.1%、应用总耗时 78.4%、费用 43.6% | 回想、整理、关联放到批量/异步，不每轮同步追加生成 |
| JSON 模式不等于结构有效 | 仍出现缺必要字段、错误层级/闭合符；12 组结构化对照 8 过 4 败 | 少用结构化输出；必须结构化时校验并拒绝整份无效结果，不删字段、不补写凑通过 |
| Provider 能力按实际配置逐项验证 | MiMo 在 JSON 模式下吞工具；Qwen3.8 Flash 原生响应出现不存在的工具名（含 `publicIntent`）；DeepSeek high 的结果不能授予 low | HTTP 200、一次冒烟、同系列另一模型都不证明能力 |
| 初见/开场会补写未提供的情节并混淆视角 | 移动流程真实验证中出现；后加第三人称约束 11/11 符合 | 叙事者开场要约束“未提供的共同经历、地点、对白保持未指定” |
| 模型误关联不能被程序升级为事实或递归扩散 | 一条合法 ID/时间的跨事件误连，旧递归 SQL 可扩散成整片关系 | 关联只作带来源的线索，直接展开并限额 |
| 模型失败不能伪装成人物沉默 | 空响应、截断、坏交接真实发生；一次有界技术恢复后 17/19 首次完成 + 2 恢复 | 技术失败与人物选择分别呈现 |
| 同话题重复样本会污染人物 | 三段同剧情重复话题引发厌烦、猜疑、反复提书 | 测试用连续人生样本；独立人生、受控样本、同请求重复分别统计 |
| 不用强制门槛制造表面通过 | 旧“普通消息必须 9/9 说话”门槛被废弃 | 评估合理回应，不强制表达或记忆数量 |

## 3. 成本与延迟参考（仅当时配置）

- DeepSeek V4 Flash / thinking=true / low / 20480：120 次机会约 ¥8.85；定向 19 次机会首段中位 6.133 s、完整 6.590 s（本地，不含部署网络与 UI）。
- 一次应用侧真实调用：11 次请求 74,531 输入 + 5,122 输出 token，约 ¥0.27。上下文输入是成本主体。
- 初见跨模型矩阵（deepseek-flash、mimo-v2.5、glm-5.3-flash、qwen3.8-flash）：GLM 曾混入英文词；MiMo 正文明显更短。

## 4. 工程与流程教训

- **先验证核心体验，再建架构**：旧项目在“聊天像不像人”被验证前，已建成 58 个页面状态与严密的事务、回执、观测体系，推翻成本极高。
- Prompt 与外部输出做逐字节快照测试；JSON 字段顺序要固定（`Map.of` 曾让顺序随 JVM 启动随机变化）。
- 测试默认用确定性模型替身；付费实验单独授权、单独记账，记录首次失败、技术恢复、最终失败与未执行的分母，结论不追溯改写。
- 改了模型、Prompt、上下文或调用链，受影响的行为结论不继承，按影响范围重验，不每次跑全矩阵。
- 概念过多会压垮体验：旧产品用户需理解出生、自我、当前认识、初见印象、牵挂、Memory、亲历、运行记录、主身份等约 10 个概念，开口前约 10 步以上。
- 响应式栈（WebFlux / R2DBC / Reactor）对低并发、同一人物串行的产品收益有限，代价是可读性、调试与自建工具循环。
